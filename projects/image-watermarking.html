Image Watermarking

Developer Platform Dashboard New feature 0 → 1

Cloudflare Images helps developers store, transform, and deliver images. Developers could already add watermarks to remote images in code, with limited capabilities, but not to images stored in Cloudflare Images or in the UI.

The ask was to bring watermarking into the dashboard and add it to the existing image variant workflow.

Finding the workflow

I started by auditing the existing Create Variant flow and mapping out where watermarking should live.

Then I explored a few directions:

  • Should watermarking be part of the existing variant settings or a separate step?
  • How should it relate to resizing and other image transformations?
  • How can developers configure the watermark while still seeing the result?

For the first phase, we focused on adding a watermark to individual predefined variants. Applying one watermark across multiple variants was left for a later phase.

Making the configuration clear

Once the workflow was defined, I explored different layouts and ways of grouping the existing settings with the new watermark settings.

The key question was: how can developers quickly understand what settings belong to the image variant, and what controls the watermark?

Through the explorations, I found that keeping all configuration in one place made the relationship easiest to understand. I paired that with a preview that updates as the settings change, so developers can immediately see how each parameter affects the result.

Two decisions

Some controls were straightforward, but some were more complex. For example, position was more complex because the watermark could be positioned relative to different edges of the image.

01. Use precise inputs to align with code

I used numeric inputs for values like opacity and scale rather than draggable controls. Developers need precise values, and these inputs also map more naturally to the way the same settings are represented in code.

02. Prioritize configuration over preview

I made the preview smaller and gave more space to the controls. This is a developer tool, so the preview needs to help users verify the result, not provide an image-editing canvas. The extra configuration space made the experience easier to scan and use.

The final experience

The final workflow lets developers add a watermark to a variant, configure its settings, preview the result, and edit or remove it later. A small feature, but a good example of how I approach developer tools: keep the experience simple without hiding the control developers need.
